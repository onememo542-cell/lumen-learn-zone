# BikeFix: Your Mechanic, Faster

# BIKEFIX — Lovable Master Build Prompt ## Egyptian Bike Maintenance Marketplace Build a production-quality, mobile-first marketplace called **BIKEFIX / بايك فِكس**. Tagline: **عجلتك محتاجة صيانة؟ إحنا نوصلّك بالخبير.** **Your bike needs service. Find the right mechanic, fast.** BIKEFIX connects: - Bike owners - Independent mobile mechanics - Bicycle workshops - E-bike technicians - Bike shops / parts partners - Operations/admin teams This is NOT a generic handyman marketplace and NOT a bike-rental app. It is a specialized marketplace for bicycle repair, maintenance, inspection, parts, mobile service, workshop booking, repair tracking, and maintenance history. The MVP supports both regular bicycles and e-bikes. Vehicle type must be configurable. --- # 1. CORE PRODUCT FLOW The strongest user journey must be: Customer reports problem → selects bike → describes issue → uploads up to 5 photos → chooses location → chooses mobile/workshop/pickup service → chooses preferred time → submits request → nearby eligible mechanics/workshops respond with offers → customer compares offers → accepts provider → provider diagnoses bike → provider sends transparent quote → customer approves/rejects additional work → repair happens → service is completed → customer receives service report → customer rates provider → maintenance history is updated This flow must be fully connected in the demo. --- # 2. MARKETPLACE MODEL The marketplace should support: - Customer-created repair requests - Provider discovery - Provider offers/quotes - Provider comparison - Location-based matching - Mobile/on-site repair - Workshop appointments - Pickup & return - Repair status tracking - Parts transparency - Maintenance history - Ratings/reviews - Disputes - Provider earnings - Admin operations Do NOT copy the branding, UI, images, text, or proprietary implementation of existing services. --- # 3. ROLES Implement: CUSTOMER MECHANIC WORKSHOP SHOP ADMIN OPERATIONS SUPPORT Create role-based navigation and permissions. Use demo accounts for every role. --- # 4. CUSTOMER DASHBOARD Show: - Active repair - Upcoming booking - My bikes - Recent services - Maintenance reminders - Saved mechanics - Service requests - Notifications Primary CTA: **Fix My Bike / أصلّح عجلتي** --- # 5. BIKE GARAGE Customers can register multiple bikes. Bike fields: - Bike ID - Nickname - Type - Brand - Model - Year - Color - Frame size - Serial number - Wheel size - Gear count - Brake type - E-bike flag - Motor type - Battery information - Purchase date - Photos - Notes Types: Road, Mountain, Hybrid, City, BMX, Kids, Folding, E-bike, Other. E-bike-specific fields must not be mandatory for normal bikes. --- # 6. BIKE PROFILE Show: - Current condition - Total services - Last service - Next recommended service - Maintenance timeline - Repair history - Parts replaced - Total maintenance spend - Documents/photos Create a clear Bike Health section. --- # 7. CREATE SERVICE REQUEST Use a guided multi-step flow. ### Step 1 — Bike Select existing bike or add new one. ### Step 2 — Problem Categories: - Flat tire - Brake problem - Gear shifting - Chain problem - Wheel problem - Suspension - Crank / bottom bracket - Electrical issue - Battery issue - Motor issue - Strange noise - Full tune-up - Cleaning - General inspection - Accident damage - Other ### Step 3 — Description Example: "الفرامل الخلفية ضعيفة والعجلة بتعمل صوت لما أمشي بسرعة." ### Step 4 — Photos Allow up to 5 photos with previews. ### Step 5 — Location Options: - Current location - Saved address - Workshop visit Egypt-friendly address fields: Governorate, City, Area, Street, Building, Floor, Apartment, Landmark, Instructions. ### Step 6 — Service Type - MOBILE_SERVICE - WORKSHOP_SERVICE - PICKUP_AND_RETURN ### Step 7 — Preferred Time - ASAP - Today - Tomorrow - Scheduled date/time ### Step 8 — Review Show bike, issue, photos, location, service type, preferred time, then: **Submit Repair Request** --- # 8. REQUEST STATE MACHINE Use strict statuses: DRAFT SUBMITTED REVIEWING RECEIVING_OFFERS OFFER_SELECTED BOOKED PROVIDER_ON_THE_WAY ARRIVED DIAGNOSING QUOTE_PENDING QUOTE_APPROVED IN_REPAIR WAITING_FOR_PARTS READY_FOR_PICKUP COMPLETED CANCELLED DISPUTED Do not allow arbitrary status changes. Every important status transition creates a timeline event. --- # 9. PROVIDER MATCHING Find eligible providers based on: 1. Service compatibility 2. Availability 3. Distance 4. Rating 5. Response time 6. Service type 7. E-bike expertise where required 8. Service area Display: **3 mechanics found near you** Do not implement complicated AI matching in MVP. --- # 10. PROVIDER OFFERS Provider offer: - Provider name - Rating - Distance - Estimated arrival - Diagnosis estimate - Labor price - Estimated parts cost - Total estimate - Warranty period - Estimated duration - Earliest availability - Service type - Notes Customer can: - Compare - Ask question - Accept - Decline Support: - Estimated price - Inspection fee - Final quote Do not force a fixed price where diagnosis is genuinely required. --- # 11. QUOTE APPROVAL Providers can discover additional work. Example: Brake cable — 80 EGP Brake pads — 180 EGP Labor — 120 EGP Total — 380 EGP Customer must explicitly approve additional work. Actions: **Approve** **Reject** Never silently increase the price. Keep quote history. --- # 12. REPAIR TRACKING Show: ✓ Request submitted ✓ Provider selected ✓ Provider confirmed ● Diagnosis ○ Quote ○ Repair ○ Completed For mobile service show provider ETA. For MVP location can be simulated, but architecture must allow future Supabase Realtime/WebSockets/SignalR. Never present simulated GPS as real GPS. --- # 13. Do not claim government certification without actual verification. --- # 15.
